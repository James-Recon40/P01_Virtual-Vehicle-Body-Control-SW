# web - VBC 웹 UI (feature/ui)

가상 차량(자동차·주변 환경·계기판)과 입력 툴바로 VehicleController를 조작하고, 05 블랙박스 테스트케이스를 시연한다.

근거: 04 SW 상세설계서 v1.1 `18_UI_연동`, 03 인터페이스 정의서 v1.4 개요 B7\~B10

## 실행

```bash
python3 web/server.py            # http://127.0.0.1:8080/ 을 브라우저로 연다
python3 web/server.py --port 9000
```

- 필요한 것: Python 3.8+, gcc (외부 패키지 설치 없음)
- 시작할 때 `src/*/*.c`를 `web/build/libvbc.so`로 빌드하고 ctypes로 불러온다. 기능 로직은 C 코드만 쓴다.
- 50 ms마다 `VehicleController_Step(now_ms)`를 호출한다 (now_ms = 0, 50, 100, ...).

## 구성

| 파일 | 역할 |
|---|---|
| `server.py` | 브리지 서버. 정적 파일 + WebSocket(`/ws`) 제공, C 모듈 빌드·호출 |
| `bridge/vbc_bridge.c` | ctypes 구조체 배치가 C와 같은지 확인하는 보조 함수 |
| `stubs/*_stub.c` | **[임시]** `src/wiper`, `src/lighting`에 `.c`가 없을 때만 링크. 항상 초기값(정지/꺼짐)을 반환 |
| `static/index.html`, `style.css`, `app.js` | 화면 |
| `static/presets.js` | TC 사전조건 프리셋 (05 문서 '사전조건' 열 기준) |
| `static/testcases.json` | 05 테스트케이스 원문 (`tools/extract_testcases.py`로 생성) |
| `tools/extract_testcases.py` | 05 엑셀 → `testcases.json`. 테스트케이스 문서가 바뀌면 다시 실행 |

## 통신 (UI 담당 결정: WebSocket)

메시지는 18 시트 규격 그대로다.

- UI → VC `{"type":"input","signals":{...}}`
  - 주기 신호 5개는 100 ms마다 한 메시지로 보낸다. 송신 중단한 신호는 메시지에서 뺀다.
  - 이벤트 신호는 값이 바뀔 때 바뀐 신호만 보낸다.
  - 연결·재연결·새로 시작 때 이벤트 신호 6개를 1회 보낸다.
- VC → UI `{"type":"output","time_ms":...,...}` 50 ms마다

18 시트 밖의 시험용 메시지:

| 메시지 | 방향 | 용도 |
|---|---|---|
| `{"type":"reset"}` | UI → 서버 | `VehicleController_Init()` 재호출, 시각 0 (TC 사전조건 '프로그램 새로 시작') |
| `{"type":"reset_done"}` | 서버 → UI | reset 처리 완료 |
| `{"type":"hello","stubs":[...],"step_ms":50}` | 서버 → UI | 연결 직후 1회, 스텁 사용 여부 표시 |
| output 메시지의 `rx` 필드 | 서버 → UI | 신호별 `last_rx_ms`(마지막 수신 시각), `received`, `value`, `since_ms`(그 값을 처음 받은 시각). C와 같은 규칙: 받은 신호는 다음 Step의 now_ms가 수신 시각, 시작 시 0. 판정에는 쓰지 않는다 |

## 화면 기능

- **주기 신호**: 시동, 기어, 속도, 조도, 강우량. 신호마다 송신 중단·재개 버튼이 있고, 모두 중단·모두 재개도 된다 (03 B8).
- **현실 주행 (UI 전용, VBC 요구사항 아님)**: 속도 슬라이더는 목표 속도다. 실제 속도는 아래 규칙으로 서서히 바뀌고, 그 값을 속도 신호로 보낸다.
  - 기어 P·R은 속도 0일 때만 들어가고 나올 수 있다. D↔N은 주행 중에도 된다
  - 시동이 꺼져 있으면 기어를 바꿀 수 없다. 시동은 주행 중에 끌 수 없다
  - 시동이 꺼져 있으면 속도(슬라이더·숫자 칸·속도 버튼)를 바꿀 수 없다. 범위 밖 값(-1, 251 등)은 C3 시험용이라 막지 않는다
  - D·R(시동 켜짐): 목표 속도까지 가속 10 km/h/s, 감속 20 km/h/s. R은 최대 20 km/h (화면의 차가 뒤로 간다, 속도 신호는 양수)
  - N·시동 꺼짐: 가속하지 않는다. 목표가 현재보다 낮으면 브레이크(20 km/h/s), 아니면 관성 감속(2 km/h/s)
  - 범위 밖 속도(-1, 251 버튼, 숫자 칸)는 **속도 센서 고장 주입**: 실제 속도와 별개로 그 값을 그대로 보낸다 (C3 범위 판정). 범위 안 속도를 고르면 해제
  - TC '사전조건 적용'은 규칙을 거치지 않고 값을 바로 세팅한다. 그 뒤로는 규칙대로 움직인다
- **범위 밖 값 (C2 시험)**: 조도·강우량 슬라이더가 유효 범위보다 넓다. 숫자 칸에는 제한 없이 입력할 수 있다. 범위 밖 값도 그대로 보낸다.
  - 조도: 슬라이더 -5000 \~ 70000 (유효 0 \~ 60000 lux)
  - 강우량: 슬라이더 -20 \~ 150 (유효 0 \~ 100 %)
  - 경계값 버튼: TC에서 쓰는 값(예: -1, 0, 999, 1000, 60001, 120)을 한 번에 넣는다
- **이벤트 신호**: 조명 스위치, 와이퍼 스위치, 도어 4개 (차량 그림의 도어를 클릭해도 된다)
- **새로 시작**: VC 초기화. '주기 신호 모두 중단 상태로 시작'을 켜면 TC-C4-02·C5용 시험 옵션이 된다.
  - 이 옵션(그리고 TC-C4-02·C5-01·C5-02 사전조건 적용)에서는 주기 신호를 새로 시작 전에 멈추고, 조명·와이퍼 스위치 OFF · 도어 4개 닫힘으로 되돌린 뒤 이벤트 신호를 1회 보낸다 (03 B8·B9)
- **테스트케이스**: 42개 TC의 목적·사전조건·절차·예상 결과를 원문으로 보여 준다.
  - '사전조건 적용'은 새로 시작한 뒤 사전조건 입력을 세팅한다.
  - 판정은 시험자가 기록을 05 문서 '예상 결과'와 비교해 직접 한다.
  - **자동 실행 (공통규칙 TC-C1-01 \~ TC-C5-02)**: 사전조건 적용 후 '테스트 수행'을 누르면 05 절차대로 입력을 넣고, 절차의 확인 시점 출력값을 '측정' 행으로 남긴다 (예: "9.9초: 전조등 꺼짐"). PASS/FAIL 판정은 하지 않는다.
    - t=0: 입력을 VC가 받은 Step(서버 `rx`), 송신 중단이면 마지막 수신 Step, 프로그램 시작이면 0. 기록의 't=0 기준' 열이 이 시각 기준이다
    - 0.49초 확인은 0.5초 전 마지막 출력(0.45초, Step 50 ms)을, 0.50초 확인에서 아직 안 바뀌었으면 +50 ms 출력도 남긴다
    - 절차 시점을 맞추려고 주기 신호 값은 다음 100 ms 송신을 기다리지 않고 1회 즉시 보낸다 ("자동 실행 즉시 송신" 행)
    - C4-02·C5-01·C5-02는 '프로그램 시작'부터가 절차라 자동 실행이 새로 시작(주기 신호 모두 중단)부터 다시 한다
    - 다시 실행하려면 사전조건부터 다시 적용한다
- **기록**: 입력 송신과 출력 변화를 time_ms와 함께 남기고 CSV로 저장한다 (증거용).
  - 't=0 표시'를 누르면 그 시점 기준의 경과 시간이 함께 기록된다.
  - 수신 시간으로 판정하는 TC(`presets.js`의 `VBC_RX_LOG_TCS`)에서 주기 신호 송신 중단을 누르면, 150 ms 뒤 그 '송신 중단' 행 옆에 마지막 수신 time_ms와 0.5초 판정 시각을 덧붙인다. 미수신 0.5초(C2·C4)는 이 마지막 수신 시각부터 센다. 서버가 이전 버전이라 수신 시각을 보내지 않으면 기록에 재시작 안내가 뜬다.
  - 유효한 속도(C3)가 바뀌면 '유효 속도' 행을 따로 남긴다. 무효가 된 경우 이유(속도·기어·시동 미수신 시간, 속도 범위 밖)도 함께 적는다.
